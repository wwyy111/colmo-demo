# 晨间唤醒策略页（本地设计提案）

入口为 index.html，原版完整演示保留于 legacy.html。使用仓库原有 HTTP 预览方式。

六个场景入口来自《智能能力输入及重点场景合并》的关键场景整理。晨间的三个任务、31 个交互与来源字段保存在 strategy-data.js，来自本次提供的场景拆解表。前台使用任务内交互编号，N 编号仅用于关联原表。

本轮细化无感唤醒交互1（N011），依据《设计呈现.pdf》：
- 时间点1：进入配置、描述偏好与权限。
- 时间点2-1：草案生成，呈现卡片和说明，之后静默等待确认。
- 时间点2-2：关键缺项、家庭规则冲突、设备能力未知的条件分支。
- 草案确认仅进入后续联测，不代表模板启用或设备已执行。

“草案生成后”的主话术与时间点2-1合并展示。冲突分支话术、App布局、输入控件是本轮设计提案。其他交互保留原表信息，细化的时间点与多通道表现待补充。App操作只保存在本页内存，刷新会重置。

## 动画素材接口

motion-assets.js 为两套形象提供同名状态和过渡映射；现阶段为空并显示占位，不播放未确认的旧动效。

建议交付：WebM + MP4 兼容文件 + PNG 封面。普通视频使用与预览区一致的深色背景；需要透明时提供带 alpha 的 WebM，并检查目标浏览器表现。

状态素材独立制作并无缝循环；过渡素材独立制作、只播放一次。时间点由用户行为驱动，不要把整个交互烘焙成定长视频。建议 30fps、统一画幅、画面中心和边距；同时提供时长、循环点、语义、进入/退出条件。

```js
// 配置后，当前状态的预览区即可通过视频控件播放。
motionAssets.line.states.waiting = {
  src: './media/line/waiting.webm',
  fallback: './media/line/waiting.mp4',
  poster: './media/line/waiting.png'
};
```

建议状态名：idle、listening、processing、statement、waiting、positive、prompt、risk、service。最终名单沿用确认后的规范，未使用状态不必先制作。

过渡使用 processing-statement、statement-waiting 等“起点-终点”键名。当前仅预留 transitions 数据接口；自动串联与语音同步在素材确定后接入。

本轮话术以文本呈现。旧版音频内容与本轮 PDF 不完全一致，暂不用于新策略页；后续按确认文本生成音效和配音。
